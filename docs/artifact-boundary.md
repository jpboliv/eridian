# Plain persisted output

The shared persona payload requires plain concise prose, in the user's language,
for files, comments, commits, PRs, issues, memory and messages to other people.
Use the artifact's template and audience. Draft from supplied context and observed
changes only. Preserve grammatical sentences, required sections, qualifications and
output-only requests. Do not invent implementation details, validation, attribution
or guarantees to make a draft sound complete. A draft is not evidence that a file
was written, a command executed or validation passed; those claims require the
corresponding supplied or observed result. This boundary is present in every level
from ticket 007 onward; ticket 009 completes the commit command and behavioral cases.

`/eridian:commit` uses a conventional subject and a body explaining why the change
matters. It does not add a Rocky quip or hardcode a model identity. Applicable host
and repository attribution instructions still apply. The command retains staged-only
scope, preview/confirmation and no automatic push. A draft-only request returns
only the message and creates no commit. Before a confirmed commit, recheck the
staged diff; changed staging requires an updated preview. A commit is reported as
created only after a successful tool result.

`/eridian:compress` is the specialized density exception, already plain and without
Rocky flavor. Its structural checks and mandatory semantic review still apply;
density never authorizes lost meaning or constraints.

The repeated evaluation cases exercise Portuguese PR bodies, JavaScript comments,
MEMORY.md constraints and conventional commit bodies. Inspect captured replies and
paired quality judgments; matching a boundary string in a prompt cannot establish
that models obey it. Shared-rule and artifact-boundary PRs are a coupled release:
human quality review remains pending, and any lost critical constraint blocks acceptance.
